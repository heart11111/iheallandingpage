## A. 설명 보강

핵심은 "설명이 부족하다"가 아니라 **이미 확보한 정보를 사이트가 쓰지 않고 있다**는 점이다.

### A1. 구매 검토자가 가장 먼저 찾는 정보가 사이트에 없다 — 제형 · 규격 · 광고심의

아세토베타 원본 제안서에 있으나 사이트에 한 항목도 없는 정보:

- **적용 가능한 제형** — 젤리 / 액상 / 물에 타먹는 분말 / 환
- **기능성 함량 및 규격** — 베타인 `0.2mg/g 이상`, 총산(초산으로서) `4.0–20.0 W/W%`
- **광고 심의 완료** — 한국식품산업협회(KFIA), 심의번호 `2501F017`.
  숙취해소 표현을 법적 허용 범위 내에서 사용할 수 있다는 근거
- **시험 설계** — 층화 무작위배정, 이중눈가림, 교차설계
- **기능성표시식품 보고 완료**

ODM/OEM 상담을 받는 사이트에서 제형과 규격이 없으면 구매 담당자는 "이 원료로 우리 제품을
만들 수 있는지"를 판단할 수 없고 결국 문의를 한 번 더 보내야 한다. 전환이 끊기는 지점이다.

**수정안** — 소재 상세 페이지에 **"공급 스펙"** 블록 신설. 4행 고정 구조:

| 행 | 내용 |
| --- | --- |
| 제형 | 적용 가능한 제형 목록 |
| 규격 · 지표성분 | 지표성분 함량 기준 |
| 인증 · 심의 | 개별인정형 / GRAS·NDI / 광고심의번호 / 기능성표시식품 |
| 시험 설계 | 대상자 · 기간 · 설계(무작위배정 · 눈가림 · 교차 등) |

정보가 있는 소재부터 채우고 없는 소재는 행을 숨긴다. 남은 PDF를 읽으면 대부분 채울 수 있을 것으로 본다.

### A2. 한국어판이 일본어판보다 정보가 적다 — 번역 누락이 아니라 데이터 구조 문제

| 정보 | 일본어 | 한국어 | 원인 |
| --- | --- | --- | --- |
| 원산지 · 개별인정형 구분 | 자연유래 10종 전부 보유 | **10종 전부 없음** | `devKorean.ts` 의 `origin` 이 일본어 값을 덮어씀 |
| "한국 최초의 이중 기능성 소재" (저분자콜라겐펩타이드 AG) | 보유 | **없음** | 동일 |
| GRAS · NDI 등록번호 (BGN4 / BORI / AD011) | 번호까지 표시 | **번호 없음** | 한국어 모드는 `strains` 를 쓰고 `originItems` 를 건너뜀 |
| 메스꺼움 개선 약 70% (9/13) — 아세토베타 | 그래프 캡션에 있음 | **없음** | 캡션이 일본어에만 작성됨 |

**코드 위치**

- 일본어 원산지 데이터: `src/lib/ingredients.ts:135, 147, 159, 171, 183, 195, 207, 219, 243`
  (예: `"インド産・韓国個別認定型素材"`, `"韓国産・韓国個別認定型素材・韓国初の二重機能性素材"`)
- 한국어 원산지 데이터: `src/lib/devKorean.ts:216, 234, 253, 270, 287, 304, 321, 341, 358, 382`
  — 원산지 · 인정구분이 전부 빠져 있음
- 덮어쓰기 지점: `src/lib/devKorean.ts:397` → `origin: copy.origin || item.origin`
- GRAS·NDI 번호: `src/lib/ingredientPptDetails.ts:214-216`
- 한국어에서 번호가 사라지는 분기: `src/components/CorporateParts.tsx:468, 776`
  → `isKorean ? materials : pptDetail?.originItems…`
- 아세토베타 메스꺼움 캡션(일본어만): `src/lib/ingredientPptDetails.ts:503`

**GRAS·NDI 번호와 개별인정형 구분은 B2B에서 신뢰도를 결정하는 정보**인데,
한국어로 보는 사람이 오히려 근거를 덜 보게 되는 상태다.

**수정안** — 언어와 무관한 사실(등록번호 · 원산지 · 인정 구분 · 균주명)은 언어별 데이터에서
빼내 **공용 필드로 승격**한다. 그러면 한쪽 언어만 채워지는 일이 구조적으로 불가능해진다.
단기적으로는 한국어 `origin` 에 원산지 · 인정구분을 추가하면 된다 — 일본어 값이 이미 있어 번역만 필요하다.

### A3. PPT에는 지표 정의가 있는데 사이트에는 없다 — AMS가 대표 사례

메인 PPT는 Testofen 슬라이드에 AMS 정의를 따로 넣어 두었다:

> AMS란? Aging Males Symptoms의 약자로 중장년층 남성의 갱년기 관련 증상의 정도를
> 설문화한 점수로서, **대한민국 식약처(KFDA)에서는 AMS를 남성 갱년기 평가의 주요
> 바이오마커로 지정**했습니다.

사이트에는 "한국 내 남성 갱년기 관련 소재 중 가장 높은 AMS 데이터를 보유"라고만 적혀 있다
(`src/lib/devKorean.ts:212`, `src/lib/ingredientPptDetails.ts:252`).
KFDA 공식 지정 바이오마커라는 사실이 빠지면서 **가장 강한 근거가 가장 약하게 전달**되고 있다.

정의 없이 쓰이는 다른 약어: TNSS · ADAS-Cog13 · SMCQ · HSI · BDI / BAI / PSQI / ISI ·
ADH / ALDH · IgE.

**수정안** — 2026-08-03에 P값에 적용한 방식(`StatLegend` + `.dh-stat-legend`)을 재사용한다.
카드 하단 조용한 각주 한 줄. AMS는 KFDA 지정 사실까지 포함해 정의하고, 나머지 약어는
처음 등장하는 곳에 괄호로 한 줄 설명을 붙인다. 모든 약어에 붙이면 문장이 다시 길어지므로
소재별 핵심 1–2개만 정의한다.

PPT 쪽 오류는 별도 목록으로 정리한다 — 영업 자료로 계속 쓰이는 문서이므로 그쪽도 고쳐야 한다.

## B. 디자인 개선

소재 상세 페이지는 정보량은 충분한데 **같은 내용이 여러 블록에 반복**되어 밀도가 낮아 보인다.
홈은 신뢰도를 깎는 요소가 몇 군데 있다.

### B1. "기본 정보"와 "원료 구성"이 같은 내용을 두 번 말한다

Testofen 페이지에서 기본 정보 표의 `Origin Ingredient` 행과 바로 아래 "원료 구성" 블록이
동일하다 — 둘 다 "호로파종자추출물 (Trigonella foenum-graecum)".
블록을 하나 더 내려가서 읽었는데 새 정보가 없으면 페이지가 비어 보인다.

**수정안** — 기본 정보에서 Origin 행을 빼고, "원료 구성" 블록에 **원산지 · 인정 구분 · 규격**을
넣어 성격을 분리한다. A1 · A2에서 확보할 정보가 바로 이 자리에 들어가므로
**중복 제거와 정보 보강이 같은 작업**이 된다.

### B2. 같은 표 안에서 라벨 언어가 섞인다

한국어 화면 기본 정보 표에서 "소재명 · 기능성 내용 · 1일 섭취 기준"은 한국어인데
`Origin Ingredient` 만 영어다. 한국어 라벨 정의(`src/lib/devKorean.ts:34-37` 인근)에
해당 키가 없어 영어 원문이 그대로 출력된다.

**수정안** — 한국어 · 일본어 라벨 세트에 `origin` 키 추가. 소규모 작업.

### B3. 같은 출처가 한 페이지에 다섯 번 나온다

Testofen 근거 그래프 4개에 "출처: Rao A et al. The Aging Male. 2016 Jun;19(2):134-42"가
각각 붙고, 위쪽 "레퍼런스" 블록에 같은 것이 또 있다. 출처는 신뢰의 근거인데 반복되면
노이즈로 읽힌다.

**수정안** — 출처는 **그래프 그룹 단위로 1회**만 표기하고 개별 캡션은 "무엇을 보여주는
그래프인지"만 남긴다. 여러 논문이 섞인 소재는 그래프에 번호를 달고 레퍼런스 블록에서
번호로 대응시킨다.

### B4. 상세 페이지 히어로만 아직 액자형이다

인덱스와 리스트 카드는 이미지를 카드 폭에 꽉 채우도록 정리했으나(2026-08-03 커밋 `8f76ea1`),
상세 페이지 히어로는 이미지가 좌측 고정 폭으로 박혀 있고 우측 텍스트가 짧아 하단 여백이 크다.
같은 사이트에서 카드와 상세의 이미지 처리 방식이 다르다.

**수정안 (방향 결정 필요)** — 히어로 이미지를 **상단 와이드 배너**로 올려 카드와 같은 어법으로
맞추거나, 2단 구조를 유지하되 이미지 높이를 텍스트 블록에 맞춘다. 전자가 카드→상세 흐름이 자연스럽다.

### B5. 홈 News 3건이 모두 같은 placeholder 이미지 · 같은 날짜다

카드 3장의 이미지가 동일한 파란 그라디언트이고 날짜도 셋 다 `2026.06.08` 이다.
B2B 방문자에게 "같은 날짜에 멈춘 뉴스"는 회사가 조용하다는 신호로 읽힌다.
**빈 뉴스 섹션은 없는 것보다 나쁘다.**

**수정안 — 둘 중 선택 (결정 필요)**

- (a) 실제 이미지와 날짜로 교체하고 갱신 주기를 정한다
- (b) 뉴스 섹션을 **"자료실 / 카탈로그 다운로드"로 교체**한다 — 드라이브의 원료소개서 PDF들이
  바로 그 콘텐츠다. 갱신 압박이 없고 B2B 전환에 직접 기여한다 ← **권장**
  (단, 공개 배포 가능한 자료인지 확인 필요 — `E. 원본 자료 취급` 참조)

### B6. 브랜드 팔레트 밖의 색과 버튼 3종이 섞여 있다

- 히어로 "JAPAN" 글자에 **분홍 그라디언트** — 브랜드 2색(남색 `#204da1` / 하늘 `#41abe1`)에 없는 색
- 버튼이 3종 — 히어로의 알약형 채움/외곽선, 카드의 알약형 외곽선, 섹션의 사각 외곽선

**수정안** — 색은 브랜드 2색 + 중립으로 한정한다. "JAPAN" 강조는 하늘색 단색으로 충분하고,
그러면 한·일 대비가 남색 · 하늘색으로 자연스럽게 읽힌다. 버튼은 **primary / secondary 2종**으로
줄이고 형태(사각)를 사이트 전체와 통일한다 — 카드 · 표 · 배지가 모두 각진 사이트에서
알약형 버튼만 튄다.

### B7. 이미지 안에 텍스트가 박혀 있어 다국어 대응이 안 된다

홈 "프로바이오틱스 소재" 카드 배경 이미지에 **"Microbiome"** 워드마크가 이미지 자체에 포함되어

## E. 원본 자료 취급 — 저장소에 커밋하지 않은 이유

**이 저장소(`heart11111/iheallandingpage`)는 공개(public) 상태다.**
(GitHub API 확인: `"private": false`, `"visibility": "public"`)

원본 PDF/PPTX를 커밋하면 다음 문제가 발생한다.

1. **제3자 상업 자료의 공개 배포** — 아미코젠 · NVP(나비팜) · BTC의 영업 제안서에는 규격,
   심의번호, 제조공정, 시험 설계가 들어 있다. 공개 저장소에 올리면 누구나 내려받을 수 있고,
   `public/` 아래에 두면 `biolabjp.com` 에서도 직접 접근 가능해진다.
2. **git 이력에서 되돌리기 어렵다** — 커밋 후 삭제해도 이력에 남아 이력 재작성이 필요하다.
3. **용량** — 전체 약 140MB(최대 단일 파일 37.6MB). Pages 배포용 저장소 크기가 크게 늘어난다.

### 권장 대안

| 방식 | 설명 |
| --- | --- |
| **비공개 저장소 분리** ← 권장 | 자료 전용 비공개 저장소를 만들어 원본을 보관하고, 이 저장소는 참조만 |
| 드라이브 유지 | 현 상태. 세션마다 `D. 자료 인덱스`의 fileId로 접근 (추가 비용 없음) |
| 공개 배포용만 선별 | 파트너사 승인을 받은 자료만 `public/downloads/` 에 두고 B5(b) 자료실과 연결 |

`B5(b) 자료실 전환`을 택할 경우, **어떤 자료가 대외 공개 가능한지 파트너사 확인이 선행**되어야 한다.
