# BIOLAB Japan — 개발 미리보기 → 퍼블리시 워크플로

라이브 사이트(`biolabjp.com`)의 본 페이지는 바로 고치지 않습니다.
먼저 `/dev` 아래에 초안을 올리고, 소유자가 **퍼블리시**라고 할 때만 실제 경로에 반영합니다.

## 흐름

1. **초안** — `src/app/dev/...` 에 미리보기 페이지를 만들고 `src/dev/registry.ts`에 등록
2. **확인** — `main`에 머지·배포되면 `https://biolabjp.com/dev/` 에서 확인 (검색·메뉴 비노출)
3. **퍼블리시** — 사용자가 「퍼블리시 / 반영 / 배포」라고 하면 초안을 `livePath` 본 페이지로 옮김

## 에이전트 규칙

- 카피·레이아웃·섹션 변경 요청이 오면 **기본은 `/dev` 초안만** 수정한다.
- 본 라우트(`src/app/page.tsx`, `src/app/company/...` 등)는 퍼블리시 지시 전에는 바꾸지 않는다.
- 예외: 버그 핫픽스, 보안, 빌드 깨짐, 사용자가 명시적으로 「바로 라이브에」라고 한 경우.
- 초안을 만들거나 고칠 때마다 `draftRegistry`를 갱신한다 (`status`, `note`, `updatedAt`).
- `/dev`는 `robots`에서 차단하고 sitemap에 넣지 않는다.
- 퍼블리시 후: 본 페이지 반영 → 레지스트리 `published` 또는 초안 삭제 → 필요 시 라이브 확인.

## 경로 규칙

| 역할 | 위치 |
| --- | --- |
| 허브 | `/dev` → `src/app/dev/page.tsx` |
| 초안 페이지 | `/dev/<이름>` → `src/app/dev/<이름>/page.tsx` |
| 레지스트리 | `src/dev/registry.ts` |
| 공유 초안 모듈 | `src/dev/drafts/` |

예시: 홈 개편 초안 → `/dev/home` → 퍼블리시 시 `src/app/page.tsx`로 승격.

## 사용자 한마디 가이드

- 「이 페이지 이렇게 바꿔줘」 → `/dev` 초안만 수정
- 「퍼블리시」「반영해」「라이브에 올려」 → 본 사이트에 완전 반영
